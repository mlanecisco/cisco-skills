# Audit follow-up

This records the implementation following the [October 15 audit](2026-10-15-library-audit.md). The original audit and evidence record remain unchanged as historical observations of commit `a25b57a`.

| Finding | Disposition |
| --- | --- |
| F05: fixture paths | Fixed. Fixtures use separate filesystem-path checks; URLs, fragments, absolute paths, and repository escapes fail. Existing files and project directories pass. |
| F06: symlink traversal | Fixed through a no-symlinks policy for installable skills, including roots, directories, and files. Extracted packages receive the same checks. |
| F14: structural verification | Partially addressed. Unknown suite and case fields fail, suite locations are explicit, and retained records and extracted packages are validated. Cross-platform CI and optional documentation checks remain pending. |
| F08: evaluation controls | Partially addressed. The teaching fixture is retained, with a neutral assessment project and evaluator-only checks added. A check-only fixture demonstrates a writing lint command. Blind product runs and selection trials remain pending. |
| F02: distribution | Partially addressed. A local builder creates versioned individual ZIPs and checksum manifests, verifies extracted contents, and refuses existing output locations. Product installation, update, and rollback trials and a shared distribution location remain pending. |
| F07: support coverage | Partially addressed. Evaluation product names include all documented products; the development suite adds native Cursor. All product and OS routes remain documented but untested in colleague walkthroughs. |
| F01: behavioral evidence | A run-record creator, consistency validator, and evaluation procedure are implemented. No completed product trial is claimed. |
| Remaining findings | Actual Narva API behavior, distribution ownership, team profiles, presentation rendering, untrusted-source cases, model-policy consolidation, and operational support ownership remain open. |

The maintainer tests check the repaired rules, archive integrity, extracted references, evidence-record invariants, and fixture acceptance checks. The deliberately defective assessment seed fails the independent checks; a correct implementation passes, including unseen records. The check-only fixture's non-writing checks preserve source hashes, while its writing lint command changes them on a disposable copy.

These are local tooling and fixture results. Follow the [evaluation guide](../evaluations.md) for fresh product sessions and the [packaging guide](../packaging.md) for colleague trials. Neither a planned record nor a verified ZIP establishes runtime quality, token savings, or a completed installation.
